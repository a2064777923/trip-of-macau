# Milestone v3.2: Traveler Gameplay Runtime and Operations Acceptance

**Status:** Shipped 2026-05-06 with accepted WeChat UAT caveat  
**Phases:** 41-45  
**Total Plans:** 16

## Overview

v3.2 turned the configured story/material/runtime platform into a playable and supportable mini-program baseline. It hardened the WeChat runtime entry path, added traveler gameplay event handling, connected traveler progress and rewards to admin operations, polished the management system IA, and closed duplicate-storyline lifecycle risk so the intended `東西方文明的戰火與共生` story is selected.

This milestone does not claim full production AR, speech, puzzle, cannon-defense, or physical-device GPS acceptance. WeChat DevTools/physical-device evidence for the full flagship journey remains an accepted caveat and is carried forward explicitly.

## Milestone Summary

**Key Decisions:**

- Do not fake WeChat/physical-device UAT. Automated and browser evidence is complete, but DevTools/device checks remain marked pending unless actually run.
- Keep advanced AR, speech, puzzle, cannon-defense, and production indoor positioning out of this milestone except as safe runtime templates/placeholders.
- Archive duplicate storylines instead of hard-deleting them when chapters, relations, sessions, progress, or exploration events still reference them.
- Keep the public mini-program runtime on managed backend data, not fallback mocks.

**Issues Resolved:**

- Mini-program story entry no longer depends on stale or legacy story selection.
- Traveler gameplay now has baseline event/reporting/reward/title feedback instead of static cards only.
- Admin support can inspect and repair traveler progress/reward state without direct database access.
- Admin story/gameplay IA and media/material surfaces are usable enough for v3.2 operations.
- Old duplicate flagship story content is removed from public runtime without orphaning related data.

**Issues Deferred:**

- `UAT-02`: concrete DevTools or physical-device flagship story smoke evidence remains pending.
- Full production AR/photo recognition, speech input, puzzle, route-coverage, cannon-defense, and indoor visual-positioning engines remain future scope.
- Story page bundle splitting remains future performance work because `pages/story/index.js` still emits an advisory size warning.
- Full approval workflow remains future release-platform scope.

**Technical Debt / Caveats:**

- `44-UAT.md` final outcome remains `BLOCKED` by missing WeChat DevTools/device evidence, by design.
- Three debug notes remain in `.planning/debug/` for mini-program runtime/content UX investigation history.
- Local `spring-boot:run` still needs `-Dmaven.test.skip=true` on this workstation because older tests reference stale constructor signatures, although compile checks pass.
