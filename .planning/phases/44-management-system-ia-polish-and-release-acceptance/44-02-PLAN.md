<objective>
Polish the v3.2 story/gameplay operational pages so tables, filters, media previews, unavailable asset states, and inline explanations are usable by operators without reading raw JSON or fighting broken layout.
</objective>

<threat_model>
## Threat Model

**Assets:** asset URLs/object keys, material package version records, traveler support state, governance findings, operator action context.

**Threats:**
- **T44-02-A Medium: operator misreads hidden/overflowing data** - Cramped columns or overflowing URLs can hide important state. Mitigation: use column widths, horizontal scroll, ellipsis tooltips, and labelled filters.
- **T44-02-B Medium: raw JSON-first workflows cause unsafe edits** - Operators may edit opaque JSON instead of structured fields. Mitigation: add inline explanations and keep JSON in advanced/debug sections only.
- **T44-02-C Medium: broken media preview mistaken for usable runtime asset** - Missing or invalid assets may look selectable. Mitigation: show explicit unavailable states and separate usable vs planned/missing assets.
- **T44-02-D Low: external URL leakage in screenshots/reports** - Full COS URLs can spill into UI captures. Mitigation: truncate visually and reveal full value only by tooltip/copy/detail when needed.
</threat_model>
