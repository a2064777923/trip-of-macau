<objective>
Create the Phase 44 release-acceptance smoke/reporting layer and final verification docs so v3.2 can close with truthful automated, browser, WeChat, caveat, and future-scope evidence.
</objective>

<threat_model>
## Threat Model

**Assets:** release evidence, admin credentials/tokens, provider/COS secrets, WeChat UAT status, milestone state.

**Threats:**
- **T44-03-A High: secret leakage in acceptance reports** - Smoke scripts can capture tokens or provider secrets. Mitigation: redact `Authorization`, `Bearer`, `token`, `refreshToken`, `password`, `apiKey`, `secret`, `sk-`, `COS_SECRET`, `SECRET_ID`, and `SECRET_KEY`.
- **T44-03-B High: false release acceptance** - Automated smoke may be mistaken for physical-device UAT. Mitigation: separate evidence sections and forbid marking unperformed WeChat/device checks as `PASS`.
- **T44-03-C Medium: non-local accidental mutation or noisy live calls** - Release smoke should not mutate production. Mitigation: default to `127.0.0.1`, block non-local base URLs unless `-AllowNonLocal`, and make quick mode read-only/report-only.
- **T44-03-D Low: evidence drift after services change** - Reports may become stale. Mitigation: include generation timestamp, exact commands, and final outcome.
</threat_model>
