<objective>
Clean up the admin information architecture for v3.2-owned story/gameplay workflows so operators can tell which entry to use and no visible sidebar entry lands on a misleading, duplicate, wrong-redirect, or unexplained shell page.
</objective>

<threat_model>
## Threat Model

**Assets:** admin navigation authority, operator understanding, content/control-plane routes, release acceptance evidence.

**Threats:**
- **T44-01-A Medium: wrong workflow edits from misleading navigation** - Duplicate or vague sidebar entries may lead operators to edit the wrong page. Mitigation: consolidate visible sidebar labels and add page purpose copy.
- **T44-01-B Medium: false readiness from placeholder pages** - Placeholder or shell-only pages may appear production-ready during release acceptance. Mitigation: keep future placeholders explicitly labelled as future work and remove them from v3.2 acceptance paths.
- **T44-01-C Low: breaking deep links while cleaning IA** - Removing routes may break existing internal links. Mitigation: keep compatibility routes in `App.tsx` when needed, but hide or redirect them to the canonical page.
</threat_model>
