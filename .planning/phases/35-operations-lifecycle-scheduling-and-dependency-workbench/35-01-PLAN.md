<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin UI -> admin backend | Authenticated operators request status changes with potential public visibility impact |
| lifecycle service -> domain tables | Shared service mutates many content-bearing tables |
| lifecycle records -> audit/history | Operation details persist admin reasons and impact snapshots |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T35-01 | Tampering | lifecycle status transitions | mitigate | Centralize allowed transitions and action-to-status mapping in `ContentLifecycleStatusSupport`. |
| T35-02 | Repudiation | lifecycle operation records | mitigate | Persist operation rows with operator, reason, request, preview hash, timestamps, and result. |
| T35-03 | Information Disclosure | preview/history JSON | mitigate | Store bounded operational metadata only; do not store secrets or provider keys in lifecycle records. |
| T35-04 | Denial of Service | dependency preview data | mitigate | Use paged/labeled DTOs and representative impact rows rather than unbounded deep object graphs. |
</threat_model>
