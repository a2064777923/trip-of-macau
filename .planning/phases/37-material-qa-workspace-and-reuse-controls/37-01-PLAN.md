<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin UI -> QA API | Authenticated operators inspect and mutate material QA states that may affect public runtime assets |
| QA service -> content/version tables | QA actions can change package item pointers and version status |
| QA consistency checker -> COS/public URLs | Checker may validate remote availability and must avoid arbitrary URL probing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T37-01 | Tampering | replace/reject actions | mitigate | Preserve immutable version rows, require notes, and update only current pointers/status fields. |
| T37-02 | Elevation of Privilege | approve/publish/rollback-like QA actions | mitigate | Reuse admin auth and Phase 36 super-admin confirmation rules for public-impacting transitions. |
| T37-03 | Information Disclosure | QA DTOs | mitigate | Keep prompts, scripts, local paths, provider details, and version provenance on admin-only endpoints. |
| T37-04 | Denial of Service | COS availability checks | mitigate | Bound checks with `maxCosChecks` and never probe arbitrary user-supplied URLs. |
| T37-05 | Repudiation | reject/replace decisions | mitigate | Persist admin id/name, note, timestamps, and version provenance for every QA action. |
</threat_model>
