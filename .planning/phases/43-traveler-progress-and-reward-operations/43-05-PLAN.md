<threat_model>
## Threat Model

**Assets:** traveler-visible rewards, titles, collectible-like game grants, admin support traces, public user state.

**Threats:**
- **T43-05-A High: invisible support correction** - A support action may write `user_game_reward_grants` but public/admin pages still omit it. Mitigation: update both admin and public read paths and smoke-check the same user after support actions.
- **T43-05-B Medium: duplicate or confusing reward representation** - Redeemable rewards and game rewards have different lifecycles. Mitigation: add explicit response fields `entryKind`, `gameRewardId`, `rewardType`, `sourceRuleId`, and `sourceEventId` so clients can distinguish redemption rows from game reward grants.
- **T43-05-C Medium: leaking raw audit payloads to public users** - Public user reward reads should expose earned reward state, not operator notes or audit internals. Mitigation: do not include `operatorId`, `grantReason`, raw audit JSON, or support annotation text in public DTOs.
</threat_model>
