<objective>
Extend the admin traveler progress read model so Phase 43 can load a complete support workbench: filtered timeline, backpack-like reward/title state, and a reward/title rule trace that explains why a traveler did or did not receive a configured outcome.
</objective>

<threat_model>
## Threat Model

**Assets:** traveler identity, session history, exploration event payloads, reward/title records, rule configuration, admin operator token.

**Threats:**
- **T43-01-A Medium: accidental data mutation from diagnostics** - Read endpoints must not mutate traveler progress or rewards. Mitigation: keep plan 01 endpoints `GET` only and implement read-only mapper/service paths.
- **T43-01-B Medium: privacy exposure through raw payloads** - Full event payloads can contain user/device context. Mitigation: timeline rows keep short `payloadPreview`; full `rawPayload` is only returned for authenticated admin and UI must display it in drawers.
- **T43-01-C Medium: false trace conclusions** - Missing links could be shown as "not eligible" incorrectly. Mitigation: rule trace must return explicit statuses such as `找不到綁定`, `規則停用`, or `資料不足`, not a silent negative.
- **T43-01-D Low: expensive unbounded timeline reads** - Large event histories can slow admin pages. Mitigation: keep page size caps and apply filters before pagination where practical.
</threat_model>
