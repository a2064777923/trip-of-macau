<objective>
Extend Phase 43 support operations so operators can preview and apply safe repairs: recompute progress, void duplicate events, resend rewards idempotently, and annotate issues with an audit trail.
</objective>

<threat_model>
## Threat Model

**Assets:** traveler progress records, exploration event history, reward/title state, operation audit records, admin identity.

**Threats:**
- **T43-02-A High: unauthorized or accidental state mutation** - Support endpoints can change user-visible state. Mitigation: keep admin auth, require preview token, explicit confirmation text, and non-empty reason for apply actions.
- **T43-02-B High: duplicate reward grants** - Resend action could grant the same reward repeatedly. Mitigation: require source event/rule/reward target, enforce a unique idempotency key for traveler-visible grant rows, and mark existing grants as already present in result summary.
- **T43-02-C Medium: destructive event deletion** - Deleting events destroys support evidence. Mitigation: use duplicate/void markers and repair notes; `deletedEventRows` remains `0` for Phase 43 duplicate void operations.
- **T43-02-D Medium: weak audit trail** - Operators must be accountable. Mitigation: every apply writes `UserProgressOperationAudit` and `SysOperationLog` with operator, reason, preview, result, IP, and target scope.
</threat_model>
