<objective>
Create a Phase 41 UAT harness that proves the flagship story route is ready to open in WeChat DevTools/local runtime, with safe evidence for backend health, public runtime data, mini-program build artifacts, generated media fallback metadata, and DevTools CLI launch readiness.
</objective>

<threat_model>
## Threat Model

**Assets:** public backend availability, JWT/dev-bypass behavior, runtime story payloads, generated media URLs, local workstation paths, operator secrets.

**Threats:**
- **Medium: secret leakage in reports** - smoke output could accidentally include tokens, API keys, provider payloads, or local paths. Mitigation: redact/ban `sk-`, `Bearer`, `apiKey`, `secret`, `promptText`, `scriptText`, `localPath`, and raw Authorization values before writing reports.
- **Medium: false UAT pass** - DevTools automation can be unavailable on Windows; the harness must record `BLOCKED` or `SKIP`, not `PASS`, when it cannot actually launch or verify.
- **Low: dev-bypass confusion** - local/devtools checks may use dev-bypass while experience/prod must not. The harness must record dev-bypass flag state and document it as local-only.
- **Low: mutable external effects** - this phase should not call provider/COS mutation endpoints. The harness should use read-only public runtime checks by default.
</threat_model>
