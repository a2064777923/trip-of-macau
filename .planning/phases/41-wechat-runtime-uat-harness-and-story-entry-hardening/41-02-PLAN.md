<objective>
Harden the mini-program story entry and media fallback diagnostics so WeChat DevTools/device testers can see whether the page is using live runtime data, fallback runtime data, playable media, fallback media, or unavailable media without relying on console logs.
</objective>

<threat_model>
## Threat Model

**Assets:** public runtime state, generated media URLs, traveler session token, API base configuration, device logs.

**Threats:**
- **Medium: leaking sensitive runtime details into UI** - diagnostics must not expose tokens, Authorization headers, provider payloads, local paths, COS object keys, or secrets. Only show non-secret values such as `USE_MOCK`, dev-bypass enabled/disabled, runtime source, and safe host labels.
- **Medium: blank story page on media/runtime failure** - unavailable runtime or media should degrade into Traditional Chinese fallback cards instead of blank screens.
- **Low: duplicate runtime events from fallback notices** - media unavailable callbacks should remain idempotent enough not to spam backend events.
</threat_model>
