<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator -> package page | Humans can trigger costed production, publish, and rollback actions from the browser |
| package page -> admin backend | The UI submits package-scoped production requests that affect live package state |
| version drawer -> operator decisions | The UI must expose enough lineage/risk context for safe publish and rollback choices |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T36-11 | Information Disclosure | secrets exposure through provider/COS metadata in UI | mitigate | Show operator-facing lineage, cost, and asset metadata only; never render secrets, raw API keys, or private provider config. |
| T36-12 | Tampering | path/object-key tampering from import modal inputs | mitigate | Submit all import data through backend validation and reflect the rejected-path errors directly in the form instead of trusting browser-side normalization. |
| T36-13 | Elevation of Privilege | unauthorized publish/rollback buttons and actions | mitigate | Keep actions package-scoped, surface super-admin confirmation state from the backend, and do not expose global generation controls. |
| T36-14 | Information Disclosure | untrusted provider URLs/downloads surfaced through narration actions | mitigate | Reuse existing backend AI helpers and package bind endpoints only; do not let the browser submit arbitrary provider download URLs. |
| T36-15 | Repudiation | lineage loss in rollback and publish history | mitigate | Render current published pointer, version numbers, verification notes, parent metadata, and rollback targets explicitly so operators can see what state they are mutating. |
</threat_model>
