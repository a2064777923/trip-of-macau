<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin UI or local tooling -> admin backend | Authenticated operators can request real provider/COS-backed production actions that affect published package state |
| production service -> COS/media/AI services | Backend-owned upload/finalize logic handles untrusted local paths, object keys, provider URLs, and external binary metadata |
| package item pointer -> version journal | Rollback and publish actions must preserve lineage instead of destroying prior usable assets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T36-01 | Information Disclosure | secrets exposure in provider/COS-backed production endpoints | mitigate | Reuse runtime-configured backend services only; never accept raw provider secrets in request payloads or persist them in version JSON. |
| T36-02 | Tampering | path/object-key tampering for local imports and COS targets | mitigate | Add `MaterialProductionPathGuard` to reject absolute paths, traversal, unsafe prefixes, and malformed object keys before any upload/import happens. |
| T36-03 | Elevation of Privilege | unauthorized publish/rollback routes | mitigate | Keep all `/production/*` routes admin-authenticated and require super-admin confirmation when cost ceilings are exceeded or rollback/publish actions demand elevated approval. |
| T36-04 | Information Disclosure | untrusted provider URLs/downloads during candidate binding | mitigate | Validate outbound candidate/provider URLs with `AiOutboundUrlGuard` before downloading or binding external binary sources. |
| T36-05 | Repudiation | lineage loss across publish and rollback history | mitigate | Persist immutable version rows with actor, cost, source type, AI linkage, verification metadata, and rollback-of-version pointers so every publish/rollback remains inspectable. |
</threat_model>
