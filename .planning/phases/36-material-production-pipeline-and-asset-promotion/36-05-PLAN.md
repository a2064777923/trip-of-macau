<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local video config -> ffmpeg builder | Job metadata controls which assets, subtitles, and COS keys become chapter videos |
| ffmpeg builder -> admin backend | Local video outputs are untrusted until imported through package-scoped backend validation |
| narration outputs -> video promotion | MAT-04 depends on real published narration and must not bypass audio readiness or publish gates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T36-21 | Information Disclosure | secrets exposure through ffmpeg/video tooling | mitigate | Keep video tooling free of provider/COS secrets and rely on existing env-backed auth/import paths only. |
| T36-22 | Tampering | path/object-key tampering in video outputs and imports | mitigate | Reuse manifest-mapped relative paths and the Phase 36 backend path guard before any video import is accepted. |
| T36-23 | Elevation of Privilege | unauthorized publish/rollback via video imports | mitigate | Keep video imports package-scoped and require the same authenticated promote/publish flow instead of shortcutting directly to published. |
| T36-24 | Information Disclosure | untrusted provider URLs/downloads chained into video jobs | mitigate | Only reference locally generated hero/audio/subtitle files that were already validated through prior Phase 36 imports; do not ingest arbitrary remote URLs in the video builder. |
| T36-25 | Repudiation | lineage loss between narration inputs and video outputs | mitigate | Store `audioItemKey`, subtitle metadata, poster fallback, and manifest output paths in the job config and imported video metadata so later rollback can explain exactly what produced each MP4. |
</threat_model>
