<objective>
Enrich the public gameplay event contract so compiled runtime steps can submit click, proximity, content-completion, pickup, task, reward, and unsupported events through `packages/server`, receive truthful Traditional Chinese feedback, and preserve backend idempotency/session semantics.
</objective>

<threat_model>
## Threat Model

**Assets:** authenticated traveler identity, story session state, exploration events, reward/title-facing feedback, event payload JSON, idempotency keys.

**Threats:**
- **T42-01-A Medium: overclaiming rewards** - The backend may not yet persist wallet/backpack/title grants for every configured effect. Mitigation: response copy must say events/outcomes were synced or already recorded, and only include sanitized configured labels without claiming irreversible grants that are not persisted.
- **T42-01-B Medium: duplicate reward/event creation** - Repeated taps could create duplicate events. Mitigation: keep `clientEventId` lookup before insert, unique-key duplicate handling, and `duplicate=true`/`eventStatus=already_synced`.
- **T42-01-C Medium: unauthorized state changes** - Stateful event endpoints must keep `requireUserId` auth enforcement and never accept anonymous writes.
- **T42-01-D Low: payload abuse** - Large or malformed payloads could affect logs or serialization. Mitigation: keep `MAX_EVENT_PAYLOAD_BYTES`, validate JSON object shape, and cap feedback label lengths.
</threat_model>
