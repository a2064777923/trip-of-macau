<objective>
Build the mini-program Phase 42 gameplay event interpreter so compiled story runtime steps become tappable baseline interactions with auth/session gating, idempotent backend submission, duplicate-as-success handling, Traditional Chinese feedback, exploration refresh, and safe unsupported-feature fallbacks.
</objective>

<threat_model>
## Threat Model

**Assets:** traveler token, story session id, local story mode context, backend event state, traveler-visible reward/progress feedback.

**Threats:**
- **T42-02-A Medium: client-only progression drift** - Local UI could show completed progress that backend rejected. Mitigation: only set synced/already-synced states from backend accepted responses; failed states remain retryable.
- **T42-02-B Medium: anonymous state mutation attempts** - Anonymous users can tap stateful cards and accidentally trigger backend writes. Mitigation: centralized `requiresSession` check and visible `請先開始故事模式`/auth copy.
- **T42-02-C Medium: duplicate reward confusion** - Duplicate responses could look like failures. Mitigation: map `duplicate=true` to `already_synced` and show `已記錄過，不會重複發放`.
- **T42-02-D Low: unsupported gameplay crash** - Advanced templates may carry unknown step types. Mitigation: classifier returns `unsupported`, no stateful write is required, and UI shows pending-feature copy.
</threat_model>
