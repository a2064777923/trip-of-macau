<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| anonymous traveler -> story page | Anonymous users may browse read-only runtime content but must not write progress. |
| story page -> public session/event APIs | Stateful actions cross into authenticated backend writes. |
| runtime step payload -> event payload | Admin-configured step fields are untrusted and must be bounded/display-only on the client. |
| local storage -> story-mode state | Stored session ids and current chapter ids can be stale or tampered with. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T39-06 | Spoofing | `startStoryModeSession` and stateful action handlers | mitigate | Use existing `requireAuth`/token behavior; never auto-create guest identities or synthetic `openId`. |
| T39-07 | Tampering | client event payloads | mitigate | Send only safe ids/codes/event names and never grant rewards/pickups locally from payload data. |
| T39-08 | Repudiation | repeated taps/network retries | mitigate | Build stable `clientEventId` with `story-runtime:` prefix plus story/session/chapter/step/event parts. |
| T39-09 | Information Disclosure | logs and verification | mitigate | Do not print bearer tokens, provider/COS secrets, prompt text, local paths, or admin-only provenance. |
| T39-10 | Denial of Service | event failures | mitigate | Catch failures, show `進度同步暫時失敗，可稍後重試`, and keep story reading usable. |
| T39-11 | Elevation of Privilege | anonymous pickup/task/reward taps | mitigate | Gate pickup/task/reward/session actions behind active authenticated story-mode session. |
</threat_model>
