<behavior>
- Anonymous mode verifies the flagship story runtime exists and contains traveler-safe story/media/step data.
- Authenticated mode runs only when `PHASE39_TRAVELER_DEV_IDENTITY` is set.
- Authenticated mode uses local/dev `POST /api/v1/user/login/dev-bypass`, starts a story session, posts duplicate idempotent events, checks exploration, and exits the session.
- The script prints no bearer token and no secret-bearing payload.
</behavior>
<action>
Create `scripts/local/smoke-phase-39-mini-program-story-mode.ps1`.

Implement strict PowerShell behavior:
```powershell
$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Add parameters from environment variables:
- `$BaseUrl = $env:PHASE39_PUBLIC_BASE_URL` defaulting to `http://localhost:8080/api/v1`
- `$StorylineCode = $env:PHASE39_STORYLINE_CODE` defaulting to `east_west_war_and_coexistence`
- `$DevIdentity = $env:PHASE39_TRAVELER_DEV_IDENTITY`

Add helper functions:
- `Invoke-JsonRequest($Method, $Url, $Body = $null, $Token = $null)` using `Invoke-RestMethod` with `Content-Type = application/json; charset=utf-8`.
- `Assert-True($Condition, $Message)` that throws when false.
- `Assert-NoBannedFields($Object, $Context)` that serializes with `ConvertTo-Json -Depth 100` and rejects exact banned strings: `promptText`, `scriptText`, `localPath`, `providerApiKey`, `apiKey`, `secret`, `estimatedCost`, `actualCost`, `qaNote`, `cosObjectKey`.

Anonymous smoke steps:
1. Call `GET $BaseUrl/story-lines?locale=zh-Hant`.
2. Find storyline by `code == $StorylineCode`; if no code match, fall back to first story whose `name` contains `東西方文明`.
3. Assert a story id exists.
4. Call `GET $BaseUrl/storylines/$storyId/runtime?locale=zh-Hant`.
5. Assert `runtimeVersion` exists.
6. Assert `chapters.Count -ge 5`.
7. Assert at least one chapter contains `compiledSteps.Count -ge 1`.
8. Assert at least one chapter contains `chapter.contentBlocks.Count -ge 1`.
9. Assert at least one serialized runtime media object includes `availability`.
10. Assert serialized runtime contains at least one of `image`, `audio`, `video`, or `lottie`.
11. Assert serialized runtime contains the unsupported placeholder text or field `unsupported`.
12. Run `Assert-NoBannedFields` on the runtime response.

Authenticated smoke steps, only when `$DevIdentity` is non-empty:
1. Call `POST $BaseUrl/user/login/dev-bypass` with body `{ devIdentity, nickname = 'Phase39 Smoke Traveler', localeCode = 'zh-Hant', interfaceMode = 'standard' }`.
2. Store `$Token = response.accessToken` but never print it.
3. Call `POST $BaseUrl/storylines/$storyId/sessions/start` with Authorization bearer.
4. Assert `sessionId` exists.
5. Post `chapter_started` to `/storylines/$storyId/sessions/$sessionId/events` with `clientEventId = "phase39-smoke:$storyId:$sessionId:chapter-started"` and payload JSON containing `chapterId`.
6. Post the exact same event again and assert response is accepted or duplicate without creating a hard failure.
7. Post `content_viewed`, `media_completed`, `pickup_interacted`, `task_completed`, `reward_acquired`, and `unsupported_viewed` with deterministic `clientEventId` values prefixed `phase39-smoke:`.
8. Call `GET $BaseUrl/users/me/exploration?scopeType=storyline&scopeId=$storyId&locale=zh-Hant`.
9. Assert `scopeType == 'storyline'` when returned.
10. Call `POST $BaseUrl/storylines/$storyId/sessions/$sessionId/exit` twice and assert neither call fails.

If `$DevIdentity` is empty, print exact non-secret line:
`Authenticated smoke skipped: set PHASE39_TRAVELER_DEV_IDENTITY to enable local/dev session checks.`

Final success line:
`Phase 39 mini-program story-mode smoke passed.`

<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| local smoke script -> public backend | Smoke exercises anonymous runtime and optional authenticated local/dev story events. |
| dev-bypass login -> smoke process | Local-only bearer token is used for verification and must never be printed or committed. |
| verification docs -> repository | Evidence documents must not include secrets, tokens, prompt text, local paths, or admin-only provenance. |
| requirements/state updates -> planning system | Traceability must reflect actual evidence, not optimistic completion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T39-17 | Information Disclosure | smoke script output | mitigate | Store bearer token in memory only, never print it, and run banned-field checks on runtime JSON. |
| T39-18 | Spoofing | authenticated smoke | mitigate | Use explicit `PHASE39_TRAVELER_DEV_IDENTITY`; authenticated checks skip unless caller opts in. |
| T39-19 | Repudiation | verification evidence | mitigate | Record exact commands and pass/skip states in `39-VERIFICATION.md`. |
| T39-20 | Tampering | requirements traceability | mitigate | Update MP-01 through MP-05 only after build/smoke evidence exists. |
| T39-21 | Information Disclosure | planning docs | mitigate | Verification caveats explicitly forbid and avoid bearer tokens, API keys, COS secrets, provider secrets, prompt text, local paths, and admin-only provenance. |
</threat_model>
